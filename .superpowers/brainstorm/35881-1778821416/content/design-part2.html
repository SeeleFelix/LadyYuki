CanvasRenderer — 统一渲染管线

一个类，两个页面通过不同配置实例化：

// LivingSpace 页面用
const renderer = new CanvasRenderer(canvas, {
  mode: 'explore',     // 可平移缩放、点选星体
  systems: ['background', 'constellation', 'voidGate', 'whispers', 'meteors'],
});

// Void Chat 页面用
const voidRenderer = new CanvasRenderer(canvas, {
  mode: 'ambient',     // 仅背景氛围，不可交互
  systems: ['background', 'constellation'],
  parallaxFollow: pointer, // 鼠标跟随视差
});

内部渲染顺序：

  1. Clear → 填满 theme.bg.void
  2. L3 氛围层 → 星云 → 银河 → 尘埃 → 背景星 → 流星
  3. L2 等待层 → 未读 Fragment 星体（脉动环）
  4. L1 叙事层 → 连接线 → 双向能量点 → 已读 Fragment 星体
  5. Whispers → 飞行文本轨迹
  6. L0 焦点层 → Void Gate → 当前交互高亮
  7. Post → Vignette → 大气透视叠加

AnimationTimeline — 叙事时间线

替代分散的 sin/cos 自由脉冲，用有结构的时间线驱动动画：

class AnimationTimeline {
  masterBeat: number;  // 全局拍子计数，按 BPM 推进
  phase: 'intro' | 'settle' | 'explore' | 'revelation';

  // 双向能量点融入叙事：
  //   intro 阶段：慢速，从 void-entry 向外扩散
  //   explore 阶段：双向全速流动，表达星体间的相互映照
  //   revelation 阶段：所有能量点加速汇聚向中心

  getEnergyDotSpeed(phase): number;
  getConnectionPulse(phase): number;
  getStarBreathAmplitude(phase): number;
}

迁移策略：渐进替换

不搞大爆炸式重写。三步走：

步内容风险
1建立 CanvasTheme + AnimationTimeline，让现有模块引用它们。不改变渲染逻辑，只改变参数来源。低
2创建 CanvasRenderer 类，将 LivingSpace.svelte 的渲染循环迁移进去。Void 页开始使用 CanvasRenderer。此时两页已经共享引擎。中
3实施视觉层级 L0-L3 的重设计调整（亮度、光晕半径、动画行为）。删除 StarBackground.svelte 和 Constellation.svelte。中

每一步都有可验证的视觉输出，你可以在每一步之后看效果、给反馈。
