三种改造方案

你选择了全部三个方向（统一引擎 + 设计系统 + 动效叙事），这是正确的——它们互为因果，应该一起解决。以下是三种不同力度的方案。

A. 最小修复 不推荐

范围：仅修复最刺眼的不一致

  • 统一三个背景色 (#04040a / #06060e / #0a0a0f → 一个值)
  • Vignette opacity 统一
  • CSS 通配符过渡限制为仅需要的元素
  • 删除死代码 (render-utils drawCrossFlare)
  • 微调动效参数降低杂乱感

Pros

  • 改动量小，一天可完成
  • 零风险，不改架构

Cons

  • 治标不治本
  • 两套引擎仍然独立
  • 未来改进仍需双倍工作
  • 动效问题只微调不重构

B. 共享渲染核心 推荐

范围：提取共享 Canvas 原语 + 设计系统，用 living-space 模块替换 Void 页的独立实现

  1. 建立 CanvasTheme：单一颜色/参数源，CSS 变量和 Canvas 渲染统一取值
  2. 提取共享原语：starColor, drawCrossFlare, drawVignette, drawNebula 等所有重复函数统一到一处
  3. Void 页接入：用 background.ts + constellation.ts 的共享模块替换 StarBackground.svelte + Constellation.svelte
  4. 统一动效参数：所有时间参数收敛到一个节奏系统

Pros

  • 从根本上消除代码重复
  • 两页视觉自动一致
  • 未来改动只需改一处
  • 保留了当前所有功能

Cons

  • 涉及 Void 页较大的重构
  • 需要仔细处理两页的微秒差异
  • 大约 2-3 天工作量

C. 全面重设计 激进

范围：从零设计视觉语言，重建渲染管线，引入视觉层级和叙事动画系统

  1. 先写 Visual Design Spec（配色、层级、动效曲线、排版）
  2. 新建统一的 CanvasRenderer 类，替代所有现有渲染代码
  3. 设计 AnimationTimeline 系统（阶段式而非循环式）
  4. 引入视觉层级：主要星体→次要星体→背景星→装饰
  5. 两页通过同一渲染器实例的不同配置驱动

Pros

  • 最好的长期效果
  • 可以追求专业级视觉质量
  • 设计意图和代码结构完全对齐

Cons

  • 工期长（1-2 周）
  • 可能丢失项目当前的"手感"
  • 过度工程化的风险
  • 当前代码量大，全量替换风险高

建议选 B，理由：它在"治本"和"务实"之间取得了平衡。方案 C 的全面重设计在当前阶段风险过高——项目还在迭代中，视觉语言还没稳定，现在就投入大量时间做"完美设计"反而可能做错方向。方案 B 先统一基础设施，让你后续的每次视觉改进都能自动惠及两个页面，这是投入产出比最高的选择。
